--- core/store.py -------------------------------------------------------------

SEVENTEEN functions, not the twelve declared in db.REQUIRED. Twelve is not
enough: without revoke_consent the consent test hits the _unavailable stub,
and without reset() there is nothing for a test fixture to call.

Key decisions:

  * claims_in_window is a GSI1 Query with the time bound in the KEY CONDITION,
    never a FilterExpression. A filter reads and bills for rows before
    discarding them.
  * Uses >= not > for the lower bound, matching memstore's `created_at >=
    since`. The brief said ">" - memstore is the behavioural reference, so
    memstore won.
  * put_filing_once is a conditional put on attribute_not_exists(SK). On a
    retry it reads the STORED row back and returns (False, stored).
  * Embeddings pack to base64 float16 inside this module and nowhere else.
    Callers only ever see list[float] or None.
  * put_claim packs an embedding but NEVER computes one.
  * No Scans on any application path. The single Scan is reset(), test-only.
  * core.clock is deliberately not imported - all time arrives as a parameter.

--- core/scoring.py -----------------------------------------------------------

  * Service mismatch is a hard 0.0 gate before any arithmetic runs.
  * Topology uses feeder_id, never coordinates:
        same feeder                     1.0
        same segment, different feeder  0.3
        adjacent segment                0.15
        otherwise                       0.0
  * "Adjacent" means consecutive numbering on the same street type in the
    same ward. The assumption is documented in the code and pinned by a test.
  * THE RENORMALISATION RULE: a missing embedding means the semantic term is
    UNAVAILABLE, not zero. Zeroed, the ceiling is 0.40 + 0.25 = 0.65, below
    TAU = 0.72 - so two houses on one trunk main reporting the same fault a
    minute apart score a perfect 1.0 on both components that ran and still
    never cluster, with nothing logged.
  * correlate() never calls embed(). No model client at module scope.
  * embed() is written but has NEVER EXECUTED - Bedrock is blocked.

5. CODE REVIEW - 9 FINDINGS, ALL REAL
===============================================================================

A review was run on the branch. Every finding was reproduced against
DynamoDB Local before being touched. Seven were fixed; two were deliberately
left and raised instead.

FIXED:

 1. HIGH / DESTRUCTIVE.  store.reset() Scans and deletes every row,
    conftest.py calls it twice per test, and test_contract.py advertises
    "PANCHAYAT_BACKEND=dynamodb pytest" as supported. Running that documented
    command without also setting PANCHAYAT_DDB_ENDPOINT silently emptied the
    shared team table. reset() now refuses a non-local endpoint unless
    PANCHAYAT_ALLOW_DESTRUCTIVE_RESET=yes.

    >>> IF ANYONE RAN THE SUITE THAT WAY AGAINST THE REAL TABLE BEFORE
    >>> COMMIT 17b9588, THE TABLE SHOULD BE CHECKED.

 2. Semantic availability was gated on "embedding is not None", which is not
    the same question as "did cosine produce a number". A zero-magnitude
    vector scored 0.6499 - below TAU - while reporting semantic_available =
    True. That is the exact silent never-clusters failure the module exists to
    prevent, wearing a label saying it did not happen. Reachable via embed("")
    or an embedding that round-trips through storage as [].

 3. The feeder index key derives from feeder_id, so a Case opened with the
    default feeder_id="" and routed later left a row at the old key forever.
    recurrence_count counts rows, so that was a permanent +1 on the number the
    escalation argument rests on - drifting toward manufacturing a pattern.

 4. Member rows are keyed one per household but carried a singular claim_id,
    so a household contributing two claims kept only the last. the_outage()
    builds that case deliberately.

 5. append_consent used two separate put_items. A failure between them left a
    live consent with no pointer, after which revoke_consent reported "unknown
    grant" and no-opped - a withdrawal silently not honoured, on the one log
    that must hold up eleven weeks later. Now one transact_write_items.

 6. .status.value / .service.value raised AttributeError on the bare strings
    memstore accepts, since these are str Enums.

 7. The subprocess test relied on cwd and used check=True, swallowing its own
    diagnostic when run from outside the repo root.

RAISED, NOT FIXED:

 8. split_case rebuilds a child's claims only from merged_from, so a case's
    FOUNDING household - present in household_ids but never in merged_from -
    splits into a child with no claims. core/memstore.py:95 has the identical
    flaw. Fixing only one side would break the parity the seam exists to
    enforce, so it must be fixed in both. memstore is shared.

 9. TAU will not transfer once Bedrock is unblocked. The renormalised path
    reaches 1.0 on topology and recency alone, while the full path needs
    sem >= 0.2 just to match the 0.65 floor. Enabling embeddings therefore
    strictly LOWERS the score for any pair whose cosine is under 1.0 - pairs
    that cluster in the demo will stop clustering in production. Wants two
    thresholds, or a sweep in both regimes.

6. OPEN ITEMS - things needing a decision or another person
===============================================================================

 1. requirements.txt is UNSATISFIABLE ON PYTHON 3.11.
    numpy>=2.5.3 requires Python >= 3.12. This machine defaults to 3.11.7, so
    "pip install -r requirements.txt" hard-fails. Anyone on a 3.11 venv is
    blocked before they start. Either the pin or the Python floor needs
    stating. Worked around here with a 3.13 venv via uv.

 2. TWO INDEX ROW TYPES ADDED THAT THE SCHEMA TABLE DOES NOT LIST.
    Needs Ali's agreement - this is the most important open item.
      - FEEDER#<feeder>#SVC#<svc> rows for recurrence_count. The Case GSI1 is
        keyed on STATUS, so there is no feeder index at all.
      - A GRANT#<grant_id> -> household_id pointer for revoke_consent, which
        receives a grant_id but needs household_id to build the PK.
    Neither query is answerable without a Scan otherwise. No new GSI was
    added, and no declared entity key was changed.

 3. CONSENT AND DISCLOSURE SORT KEYS CARRY A UNIQUIFIER.
    CONSENT#<granted_at> alone collides when a household grants two scopes in
    one tick, and the second silently overwrites the first. memstore keeps
    both. An append-only log that drops rows is the one bug this table must
    not have.

 4. THE GATE HAS NOT RUN AGAINST THE REAL TABLE.
    No AWS credentials on this machine (~/.aws holds only an empty sso/).
    store.py reads an optional PANCHAYAT_DDB_ENDPOINT for local runs; it is
    unset in production. Re-run when credentials land.

 5. TABLE CREATION HAS NO HOME IN THE REPO.
    The create_table.py used here lives in a scratchpad, because table
    creation is deploy - Ali's lane - and the brief said stay inside
    store.py and scoring.py. It needs a home in scripts/.

 6. test_virtual_clock_compresses_a_statutory_week IS FLAKY BY CONSTRUCTION.
